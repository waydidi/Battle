## Engineering decisions made in Phase 0/1

| Date | Decision | Why |
|---|---|---|
| 2026-10-20 | Unity 6 LTS + URP, new Input System (legacy Input Manager still supported in code) | Current LTS; Input System is the default for new Unity 6 projects |
| 2026-10-20 | Game rules live in an engine-free assembly (`Assets/Scripts/Core`, `noEngineReferences`) | Same code can run on the authoritative server and in plain .NET tests/CI |
| 2026-10-20 | Prototype scene is generated by an editor menu, not hand-built | Reproducible, reviewable in Git, no binary scene merge conflicts early on |
| 2026-10-20 | Networking stack **not chosen yet** | Compare NGO / FishNet / others with a spike at the start of Phase 3 |
| 2026-10-21 | Warrior Sunspire tree uses the **15 skills from the UI mockup** (3 branches × 5) | The mockup is the art/UI target; the earlier 10-skill list stays as reference |
| 2026-10-21 | "SP" = stamina bar only; tree currency is **Skill Points** | The mockup used "SP" for both; one meaning avoids confusion |
| 2026-10-21 | HP/SP formulas retuned so Storm shows 4,520 HP / 1,280 SP | Match the mockup HUD |
| 2026-10-21 | Storm model generated by a Blender script; FBX for Unity, GLB for the web | Reproducible original placeholder art with no licensing risk |
| 2026-10-21 | A browser (three.js) build of the slice is kept in `web-prototype/` | Lets the design be played and reviewed on any phone without installing Unity |
